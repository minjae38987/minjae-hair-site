# GA4 테스트 클릭의 명시적 구분 — 2026-11-09

## 구현
기존 `naver_booking_click` 이벤트와 개인정보 수집 동의 흐름은 유지합니다.
예약 버튼 클릭 이벤트에 `traffic_validation_status` 파라미터를 추가합니다.

- `qa_marked`: 사용자가 `?analytics_qa=1`을 명시적으로 열고 동일 탭에서 실행한 검증 클릭.
- `unclassified`: 그 외 모두. **실제 고객으로 확인된 트래픽을 뜻하지 않습니다.**
- `?analytics_qa=0`: 현재 탭의 QA 마커 해제.

QA 마커는 현재 탭의 sessionStorage에 저장됩니다. 다른 탭·브라우저의 클릭은 자동으로 QA라고 표시되지 않습니다. 불특정 고객을 QA로 식별하는 추적 장치가 아닙니다.

## 활용 방법
1. 기존 사이트 URL에 `?analytics_qa=1`을 붙여 **본인의 검사 탭**에서만 QA를 의도적으로 표시합니다.
2. 사이트 방문 통계 수집을 동의한 상태에서만 GA4 이벤트 전송이 이루어집니다.
3. GA4에서 이벤트 범위 사용자 정의 측정기준으로 `traffic_validation_status`를 등록하면 향후 `qa_marked`와 `unclassified` 이벤트를 구분할 수 있습니다.
4. **이전 17회 클릭에는 해당 파라미터가 없으므로 소급 분류할 수 없습니다.** 추후에도 `unclassified`를 진짜 고객 유입으로 간주하지 마세요.
5. 고객별 식별자·예약번호·연락처를 전송하지 않습니다.

## 범위와 한계
이 방식은 본인이 수행한 테스트의 일부를 표시하는 최소 기능입니다. 자동 필터링이나 GA4의 내부 트래픽 제외 설정을 대신하지 않습니다. 자동 측정에서 빠진 QA는 여전히 `unclassified`로 남을 수 있습니다.
실제 예약 완료는 네이버 예약·매장 결제 기록에서 검증합니다.
